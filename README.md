# Does a music Transformer know what key it is in?

A symbolic music Transformer is trained on notes alone — its vocabulary contains bar
lines, metric positions, absolute pitches and durations, and no key, chord or degree
token. This repository asks whether such a model builds an internal representation of
**key** that it actually uses, and answers it the way the Othello-GPT line of work
answers questions about board state: don't just read the state off the activations,
**overwrite** it and check that the model's own output follows.

It does. On held-out prompts whose design was frozen before the test ran, replacing the
key subspace at one layer makes the continuation land in the key we installed for
**0.355** of the 1,100 continuations (100 prompts x 11 target keys), against **0.039**
for a random subspace of the same DIMENSION and **0.056** for one matched in dimension
AND displacement (12/12 target keys separate; guard-passing rate 0.84). A pre-registered
minor-key condition replicates it at **0.495** against **0.003** and **0.026**. Reading the key is easy almost
everywhere in the network — the probe reaches macro-F1 **0.927** at layer 4 and stays
flat across layers 2-6 — while the editing effect varies strongly across those same
layers, so a readable layer is not necessarily a layer where replacing the key changes
the output. On the control-corrected probe margin the two peak at the same layer in this
model; the clearer separation is in a public checkpoint, where the margin is high at
layers whose edit does nothing (see the supplement).

Every number above is recomputed from a ledgered artifact under `results/` by
`experiments/figures/collect_paper_numbers.py`. `results/` is NOT committed (see
`.gitignore`): the artifacts are produced by the runs recorded in `RESULTS_LEDGER.md`
and are regenerated by re-running them. See **Scientific integrity** below.

## Layout

```
docs/SPEC.md              the protocol, frozen: decision rules and thresholds
docs/KNOWLEDGE.md         background and related work
docs/FILE_MAP.md          old -> new paths, for reading older ledger entries
docs/CONFIRMATORY_FREEZE.md  the final test's design, committed before it ran
CHANGELOG.md              every protocol change, with its reason
RESULTS_LEDGER.md         append-only: one row per run, with git and config hashes

src/                      the library — no experiment logic
  tokenizer/              leak-free vocabulary (unit-tested for leak-freedom)
  datagen/                the synthetic corpus, and the real-chorale reader
  model/                  the Transformer and its training loop
  probing/                probes, the C1-C3 controls, equivariance
  intervene/              subspaces, the edit, its controls, the sweep
  publicmodels/           one adapter per public pre-trained model
  eval/                   key estimation, the metrics, the quality guard
  analysis/               statistics and figures — reads only from results/

experiments/              one directory per experiment (see experiments/README.md)
tests/                    the gates: vocabulary leak, label alignment, sham identity,
                          key-estimator sanity, adapter contract, and a scope check
                          over every script (no name read unbound or after `del`)
configs/                  every seed and threshold; no magic constants in src/
paper/                    the manuscript
```

`results/` and `data/` are not tracked.

## Reproducing

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest tests/ -q          # 191 tests, the gates named above

.venv/bin/python experiments/data_and_models/generate_corpus.py
.venv/bin/python experiments/data_and_models/train_models.py
.venv/bin/python experiments/data_and_models/quality_gate.py     # gate before probing
.venv/bin/python experiments/runners/run_phase_a.sh              # probes + equivariance
.venv/bin/python experiments/editing/freeze_quality_guard.py     # guard BEFORE any edit
.venv/bin/python experiments/editing/edit_sweep.py --model-dir results/models/R-Aug_s0
.venv/bin/python experiments/editing/verdicts.py --model-dir results/models/R-Aug_s0
```

`experiments/README.md` lists every experiment, the question it asks, and the order
they run in. `--help` on any script gives its arguments.

Two stages are deliberately ordered and will refuse to run out of order: the quality
gate is computed before any intervention work, and the perplexity budget is frozen
before any edit, so neither can be tuned to a result.

adapter records which checkpoint a run used in that run's artifact.

## Scientific integrity

`docs/SPEC.md` is a pre-registration. Its decision rules and thresholds are frozen; if
an implementation reality forces a change, the change is appended to `CHANGELOG.md`
with its reason and never made silently. Beyond that, four rules govern this repository
and are worth stating plainly because they constrain how results may be reported:

1. **No number is fabricated, estimated, or placeheld.** Every number in a report,
   figure, or draft traces to an artifact under `results/` produced by a logged run.
   Rounded strings are recomputed from the artifact, never copied from an earlier
   summary. A cell that has not been run reads "TBD (run required)".
2. **Every run is ledgered** in `RESULTS_LEDGER.md` — datetime, git hash, config hash,
   seeds, artifact paths — append-only.
3. **Failures and negative results are reported.** Exclusions only by criteria the SPEC
   states in advance.
4. **`analysis/` reads only from `results/`.** Generation code never touches analysis
   output.
