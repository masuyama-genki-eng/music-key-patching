% 概要
\begin{abstract}
% 近年の研究は音楽生成モデルの活性から調を読み取れることを示しているが，調が読めることは，モデルが作曲中にそれを使っていることを示さない．
% 我々は，記号が音高と時間だけを表し，調を表す記号を一つも含まない記号音楽で Transformer を訓練する．
% そのうえで，生成の途中で，活性のうち調を担う 24 次元分を，別の調でその部分が平均的に取る値に置き換える．与える8小節の音符は1音も変えない．
% モデルが内部の調を参照しているなら，継続はいまや我々が書き込んだ調に従うはずである．
% 実際に従う：層と方向を事前に決め，それ以前のどの実験も触れていない楽曲で1度だけ行った最終テストで，継続が書き込んだ調に入る割合は 0.356，すなわち3回に1回以上であり，同じ 24 本をランダムに選んだ場合は 0.039 である．12 の調すべてが多重比較補正後に分離する．
% ランダム編集の変化を，活性を動かす距離が編集とちょうど同じになるまで引き上げても 0.056 にとどまるので，効くのは押す強さではなく，どの方向を編集するかである．
% この変化は，モデルが自分の書いた音符から調を読み直した結果ではない：何も生成していない時点で，新しい調の音に置かれる確率がすでに +0.26 上がっており，ランダム編集では +0.02 である．
% モデルが音高を選ぶ位置だけに書き込んでも何も起こらないので，この編集は音高の確率を直接押しているのではない．
% どちらの結果も，実音楽で訓練された公開モデルへそのまま移る（ランダムベースラインの 7.8 倍，12/12 調）．
% 以上より，音楽 Transformer は調を計算し，我々が上書きできる形で保持し，作曲中にそれを参照している．テストベッドを公開する．
Recent work shows that we can read the musical key out of the activations of a music generation model, but reading a key does not show that the model uses it while it writes.
We train Transformers on symbolic music whose symbols name pitches and timing only, never a key.
While the model generates, we then replace the $24$-dimensional part of the activation that carries the key with the value that this part takes, on average, in a different key, and we leave every note of the eight-bar input untouched.
If the model consults an internal key, the continuation should now follow the key we write in.
It does: with the layer and the directions chosen in advance, on music no earlier run had touched, the continuation ends in the key we install for $0.356$ of the prompts---more than one in three---against $0.039$ when we edit $24$ randomly chosen directions instead, and all $12$ keys separate after correcting for multiple tests.
Rescaling the random edit to move the activation exactly as far leaves it at $0.056$, so what matters is which directions we write to, not how hard we push.
The shift is not the model reading the key back off its own notes: before it generates anything, the probability it assigns to the notes of the new key already rises by $+0.26$, against $+0.02$.
Writing the key only where the model chooses pitches does nothing, so the edit is not a direct push on pitch probabilities.
Both results carry over to a public model trained on real music ($7.8\times$ the random baseline, in $12/12$ keys).
A music Transformer therefore computes its key, holds it in a form we can overwrite, and consults it while it writes; we release the testbed.
\end{abstract}

% 1. はじめに
\section{Introduction}
\label{sec:intro}

% P1 背景。トピック文＝主張，結び＝問いの提示で次段落へ橋渡し。
% 音楽生成モデルは，自分が何の調にいるかを知っているかのように振る舞う．
% 調とは，ある一節が「ホーム」として扱う少数の音高の集合である：音楽はそこに落ち着き，離れ，また戻ってくる．
% 訓練済みモデルはこの型を長い区間にわたって再現し，しばしば途中で別の調へ移ってからまた戻ってくる．
% この流暢さは，正確に述べられる1つの問いを生む：モデルは内部のどこかで調を追い続けているのか，それとも音符の表面的なパターンを再現しているだけなのか．
Music generation models behave as if they knew what key they were in~\cite{hadjeres2017deepbach,huang2019musictransformer,copet2023musicgen}.
A key is the small set of pitches that a passage treats as home: the music settles on them, leaves them, and comes back.
Trained models reproduce this pattern over long spans, and they often move to another key and return.
Their fluency raises one question that we can state precisely: does a model track the key somewhere inside, or does it only reproduce surface patterns of notes?

% P2 現状と問題。詳細な整理は第2節に譲り，ここではギャップだけを述べる。
% 既存の証拠はこの問いに答えられない．示しているのは，調が読めるということだけである．
% 分類器は活性から調を読み出せ，ステアリングは調を押せるが，どちらも，我々が設定した調にモデルが従うことは示せない（第2節）．
% ゲームの分野は内部状態を書き換えることでこの種の問いを決着させており，音楽の調でそのテストを行った研究はない．それを我々が供給する．
The evidence we have cannot answer that question, because it only shows that the key is readable.
Classifiers can read the key out of the activations~\cite{syntheory2024}, and steering can push it, but neither shows that the model follows a key that we set (Section~\ref{sec:related}).
Game domains settle such questions by overwriting internal state; no study has run that test for musical key, and we supply it.

% P3 着想。トピック文＝解決策の提示，結び＝テストの読み方（この論文の論理の要）。
% 我々はこの問いを，モデルの内部で調を変え，その後に何を書くかを見ることで決着させる．
% テストの核にあるのは1回の置き換えである：ある層の活性のうち調を担う部分を取り，別の調でその部分が取る値を書き込み，入力の音符は1つも動かさない．これによりモデルの内部状態だけが変わる．
% 音楽の調は，この種のテストの状態変数として大半の属性より適している．
% 第一に，音楽理論が調をモデルの外側で定義するので，我々が自分で作った基準でモデルを採点することにならない．
% 第二に，語彙は調を名指ししないので，調は音高そのものから来るしかない．
% 第三に，調の音階は7つの音高を並べた決まった一覧なので，編集の成否は音符を数えれば確かめられる．音楽を採点する審査器を訓練する必要がない．
% したがってこのテストの読み方は明快である：書き込んだ値に音楽が従えばモデルはその値を参照していたのであり，従わなければ調は読めるだけだったことになる．
We settle that question by changing the key inside the model and looking at what it writes next.
At the core of our test is a single replacement: we take the part of one layer's activation that carries the key and write in the value that this part takes in a different key, while every note of the input stays where it was, thereby changing the internal state of the model and nothing else.
Musical key suits such a test better than most attributes do.
First, music theory defines a key outside the model~\cite{krumhansl1982}, so we do not grade the model against a standard of our own making.
Second, our vocabulary never names a key, so the key can only come from the pitches themselves.
Third, the scale of a key is a fixed list of seven pitches, so we can check the edit by counting notes instead of training a judge to grade the music.
The test therefore reads cleanly: if the music follows the value we install, the model was consulting that value, and if it does not, the key was only readable.

% P4 提案と貢献。トピック文＝期待値調整（何を主張し何を主張しないか），結び＝以降は証拠の確認であるという見通し。
% 本論文は分析論文である：新しい生成手法は提案せず，生成品質の向上も主張しない．
% 貢献は以下のとおりである．
% 1）この問いのためのテストベッドを世に出す：調が漏れない語彙，全音符に付いた真の調，事前に固定した評価手続き．
% 2）調を上書きすると音楽が書き込んだ調へ移ることを示す——それ以前のどの実験も見ていないプロンプトの上で，そして実音楽で訓練された公開モデルにおいても．
% 3）この効果が見かけのものではないことを示す：モデルが何も書かないうちに次の音の確率へ現れ，モデルが音高を選ぶ位置だけに編集を限ると消える．
This paper is an analysis paper: we introduce no new generation method, and we claim no gain in generation quality.
Our contributions are as follows.
1)~We introduce a testbed for this question: a vocabulary that cannot leak the key, the true key on every note, and an evaluation protocol fixed in advance.
2)~We show that overwriting the key moves the music into the key we write in---on prompts that no earlier experiment had seen, and also in a public model trained on real music.
3)~We show that this effect is not an artifact: it appears in the next-note probabilities before the model writes anything, and it disappears when we restrict the edit to the positions where the model chooses pitches.

% 2. 関連研究
\section{Related Work}
\label{sec:related}

% 章の役割：2つの流れを概観すると宣言する。読者に地図を渡す2文のみ。
% 本節では2つの研究の流れを概観する：モデル内部の調を読み取る・押す音楽研究と，内部状態を書き換えるゲーム研究である．
% 後者が，我々が音楽へ持ち込むテストである．
In this section we review two lines of work: music studies that read or push the key inside a model, and game studies that overwrite internal state.
The second is the test we bring to music.

% 2.1 メッセージは1つ：「音楽で分かっているのは，調が読める・押せるところまで。使っているかは誰も検証していない」。
\subsection{Probing and Steering in Music}
% 音楽モデルの既存研究が示しているのは，調が読めることであって，モデルがそれを使っていることではない．
% プロービング研究は，活性の上で小さな分類器を訓練し，調を含む音楽理論の概念を読み出す．
% ステアリング研究は，言語モデル由来の技法を使う：学習したベクトルを活性に足すと，出力の属性が動く．
% 本研究と同様に，どちらもモデルの内部に働きかけ，再訓練なしに推論時に介入する．
% しかし読めることは使っていることを意味しない：モデルは信号を内部に持ったまま，書くときにそれを無視できる．
% ステアリングも答えられない：ホ長調の方向へ押しても，モデルの調がホ長調に設定されるわけではないので，モデルが従うべき「書き込まれた調」がそもそも存在しないからである．
% 我々の問いはその一歩先にある：調を書き込み，音楽がそれに従うかを見る．
Existing work on music models shows that the key is readable, not that the model uses it.
Probing studies train a small classifier on the activations and read out music-theory concepts, including the key~\cite{syntheory2024}.
Steering studies use a technique adapted from language models~\cite{li2023iti,zou2023repe}: they add a learned vector to the activations, and an attribute of the output moves~\cite{smitin2024,musicrfm2026}.
Similar to our work, both act on the inside of the model, at inference time and without retraining.
Reading, however, does not mean using: a model can carry a signal inside and still ignore it when it writes~\cite{hewitt2019control,belinkov2022probing}.
Steering cannot answer it either: pushing toward E major never sets the model's key to E major, so there is no installed key for the model to follow.
Our question sits one step further: write the key in, and watch whether the music follows.

% 2.2 メッセージは1つ：「ゲーム分野はその一歩（書き換えテスト）を確立済み。我々はそれを音楽に持ち込み，音楽に必要な2つの道具を足す」。
\subsection{Causal Tests by Overwriting}
% ゲームの分野は，その一歩をすでに踏み出している．
% プロービングはゲームでも知識を示した：AlphaZero の内部からチェスの概念を追跡している．
% しかし「使用」を決着させたのは書き換えである．
% 手の予測だけで訓練された Transformer は，内部にオセロの盤面を作る．
% 研究者がその盤面を偽の盤面に書き換えると，モデルは偽の盤面のほうで合法な手を指す．
% 入力は何も変わっていないので，新しい指し手は書き込まれた値からしか来ようがない：モデルは盤面を使っている．
% この型の介入は activation patching と呼ばれ，同じテストは現在，チェスを指す言語モデル，迷路，強化学習の学習済み環境シミュレータに及んでいる．
% ゲームでは手が合法か違法か一目で決まるのと異なり，音楽の継続は単純な正誤を持たない．
% 我々の編集はこの patching テストを音楽へ持ち込むものであり，第3節では音楽で必要になる2つの道具——継続がどの調にいるかの判定基準と，編集が音楽を壊してよい上限——を用意する．
Game domains have already taken that step.
Probing showed knowledge in games as well: it traced chess concepts inside AlphaZero~\cite{mcgrath2022chess}.
Use, however, was settled by overwriting.
A Transformer trained only to predict moves builds an Othello board inside itself~\cite{li2023othello,nanda2023emergent}.
When researchers overwrite that board with a fake one, the model plays the moves that are legal on the fake board.
Nothing in the input changed, so the new moves can only follow from the value that was written in: the model uses its board.
Interventions of this type are called activation patching~\cite{geiger2021causal,meng2022rome}, and the same test now covers chess-playing language models~\cite{karvonen2024chess}, mazes~\cite{maze2024}, and learned environment simulators in reinforcement learning~\cite{iris2026}.
Different from a game, where a move is legal or illegal at a glance, a musical continuation is never simply right or wrong.
Our edit brings this patching test to music, and Section~\ref{sec:method} adds the two tools music needs: a criterion for which key a continuation is in, and a limit on how much an edit may damage the music.

% 3. 手法
\section{Method}
\label{sec:method}

% 本節では，本論文の2つの解析——調を読むことと，調を書き換えること——をこの順に述べる．
% 記法として，層 ℓ・位置 t における活性を h_ℓ(t)，そこでの真の調を κ(t) と書く．κ(t) は 24 クラス（12 の主音それぞれに長調と短調）を取る．
% プローブは 24 クラスすべてを判別するが，編集が書き込むのは 12 の長調だけである（5.6節）．
% データ・モデル・評価手続きは第4節で述べる．
In this section we present the two analyses of the paper, first reading the key and then overwriting it.
As notation, write $h_\ell(t)$ for the activation at layer $\ell$ and position $t$, and $\kappa(t)$ for the true key there, one of $24$ classes ($12$ tonics, each major or minor).
The probe distinguishes all $24$ classes; the edits install the $12$ major keys only (Sec.~\ref{sec:limits}).
Section~\ref{sec:exp} describes the data, the models, and the evaluation protocol.

% 3.1 調の読み方
\subsection{How We Read the Key}
% 第1の問いは，調が音符そのものからよりも h_ℓ(t) からのほうが読み取りやすいか，である．
% 活性は音符から計算されるので，調の情報が中にあること自体は当然である．問うているのは，モデルがそれを読み取りやすい形に加工したかどうかである．
% h_ℓ(t) から κ(t) を予測する線形プローブを訓練し，訓練とテストは曲単位で分ける．
% プローブの高得点は，それだけでは証拠にならない：モデルが調について何も計算していなくても，高得点を生む要因が3つあるからだ．
% 第1に，強力なプローブは意味のないラベルからでも点を取ってしまう．そこで各曲の中で調ラベルをシャッフルし，そのでたらめなラベルに対する点数を測る．
% これは中身と無関係に届く床なので，プローブとベースラインの差——以後マージンと呼ぶ——を報告するときは必ずこの床を引く．
% 第2に，未訓練のネットワークの活性でも，ある程度の点は出るかもしれない．そこで同じプローブを未訓練のモデルにも走らせる．
% 第3に，音符そのものが調をほぼ明かしているなら，モデルは何も足していない．
% そこで音符だけから調を予測するベースラインを置く：12 のピッチクラス（C，C♯，…，B）の出現回数を数え，その回数から調を当てる——回数へのロジスティック回帰と，各調の音階と照合する Krumhansl–Schmuckler（KS）法を，W∈{8,…,64} トークンの窓で行う．
% プローブが何をどれだけ上回れば成功かは，4.3節で固定する．
Our first question is whether the key is easier to read from $h_\ell(t)$ than from the notes themselves.
The activation is computed from the notes, so the key is in there in some form by default; what we ask is whether the model has reshaped it into a form that is easy to read.
We train a linear probe~\cite{alain2017probes,belinkov2022probing} to predict $\kappa(t)$ from $h_\ell(t)$, and we split train and test by piece.
A high probe score is not evidence on its own, because three things can produce one without the model computing anything about the key.
First, a powerful probe can score points even on meaningless labels, so we shuffle the key labels within each piece and measure the probe on the shuffled labels~\cite{hewitt2019control}.
That score is a floor the probe reaches regardless of content, and we subtract it from every probe-minus-baseline difference---every margin---that we report.
Second, the activations of an untrained network might already score something, so we run the same probe on an untrained model.
Third, if the notes themselves almost give the key away, then the model has added nothing.
We therefore add a baseline that predicts the key from the notes alone: it counts how often each of the twelve pitch classes (C, C$\sharp$, \dots, B) occurs and guesses the key from those counts, by logistic regression and by Krumhansl--Schmuckler (KS) matching~\cite{krumhansl1990,temperley1999ks} against the scale of each key, over windows of $W\in\{8,\dots,64\}$ tokens.
What the probe must beat, and by how much, is fixed in Section~\ref{sec:measures}.

% 3.2 調の書き換え方
\subsection{How We Overwrite the Key}
\label{sec:methodB}
% 第2の，そして主要な問いは，生成中に調を上書きしたとき音楽がそれに従うかである．
% 安定した調の8小節をプロンプトとして与え，第9小節以降，モデルが生成する各位置で1つの層の活性を，activation patching の文献に従って次のように編集する．
% ここで V は調を担う方向を並べたもの，P_V=VV^T は活性のうちその方向に沿う部分だけを取り出す射影，μ_{κ*} は書き込みたい調の平均活性である．
% 平易に言えば：活性のうち調を担う部分を別の調の同じ部分に取り替え，他には何も触らない——特に，プロンプトには決して手を加えない．
% 方向の作り方は3通り試す：プローブの重み，調ごとの平均活性，そして編集そのものに合わせて最適化した方向である．どれを使うかは 4.4 節の探索が選ぶ．
% 同じ編集は，生成を伴わない読み取りにも使える：調に中立な小節記号と拍位置を我々自身が付け足し，第9小節の境界で編集を適用し，何も生成させずに次の音の確率を読む（5.3節）．
Our second question, the main one, is whether the music follows the key when we overwrite it during generation.
We prompt the model with $8$ bars in a stable key, and from bar~$9$ on we edit one layer's activations at every position it generates, following the activation-patching literature~\cite{geiger2021causal,meng2022rome}:
\begin{equation}
h \;\leftarrow\; h - P_V h + P_V\,\mu_{\kappa^{*}},
\label{eq:edit}
\end{equation}
where $V$ collects the directions that carry the key, $P_V{=}VV^{\!\top}$ keeps only the part of the activation that lies along them, and $\mu_{\kappa^{*}}$ is the average activation of the key we install.
In plain terms, we swap the key-carrying part of the activation for the same part of a different key and touch nothing else---in particular, we never change the prompt.
We build $V$ in three ways: from the probe weights, from the per-key average activations, and from directions optimized for the edit itself~\cite{geiger2024das}; the search of Section~\ref{sec:confirm} selects among them.
The same edit also supports a generation-free reading: we append a key-neutral bar mark and beat position ourselves, apply the edit at the bar-$9$ boundary, and read the next-note probabilities without generating anything (Sec.~\ref{sec:nextpitch}).

% 結果は5つの比較で挟み込む．
% 第1は，ランダム方向のベースラインである：調の方向ではなく，ランダムに選んだ 24 本の方向へ同じ書き込みを行うので，書き換える数の個数は同じになる．
% ただしこのベースラインは活性を編集ほど遠くまで動かさない：変化ベクトルの長さを各書き込み位置で測り，位置・プロンプト・標的の調で平均すると，編集は 34.6，ベースラインは 24.1（比 1.44）で，活性そのものの平均長は 169 である．
% 我々の計画は距離も一致させるよう求めていたが，実装は本数だけを一致させたので，このずれを隠さず記録する．
% そこで第2として，同じ 24 本のランダム方向のまま，変化の距離をちょうど 34.6 に引き上げたベースラインを加える．これで「押しが強かっただけ」という説明の余地が消える．
% 第3は何もしない編集で，編集なしの出力をトークン単位で再現しなければならない．
% 第4は，ある層の方向を別の層に当てるもので，方向がその深さに固有かどうかを教える．
% 第5は，プロンプト自体を移調するもので，出力がそもそもどこまで動きうるか，すなわち上限を教える．
% まとめると，プローブは調がそこにあるかを教え，これら5つの比較はモデルがそれを使っているかを教える．
Five comparisons bound the result.
The first is a random-direction baseline: it writes into $24$ randomly chosen directions instead of the key directions, so it overwrites the same number of numbers inside the activation.
This baseline does not move the activation as far as the edit does: measuring the length of the change at each written position and averaging over positions, prompts, and target keys gives $\|\Delta\|=34.6$ for the edit against $24.1$ for the baseline, a ratio of $1.44$, on activations of mean length $169$.
Our plan had asked the distances to match as well, the code matched only the number of directions, and we log that gap instead of hiding it.
The second comparison therefore keeps the same $24$ random directions and scales the change up to a distance of exactly $34.6$, which removes the explanation that we simply pushed harder.
The third is a do-nothing edit that must reproduce the unedited output token by token.
The fourth applies one layer's directions at a different layer, which tells us whether the directions belong to that depth.
The fifth transposes the prompt itself, which tells us how far the output can move at all and so gives an upper bound.
In sum, the probe tells us whether the key is there, and these five comparisons tell us whether the model uses it.

% 4. 実験
\section{Experiments}
\label{sec:exp}

% 4.1 データ
\subsection{Data}
% 全ての音符で真の調が必要なので，訓練データは自分たちで生成する．
% 教科書的な和声規則に従うプログラムが，調を選び，各和音を4声に書き，任意で旋律を加える．
% 訓練・検証・テスト用に 200k/10k/10k 曲を生成し，各曲は 278–508 トークンで 0–3 回の転調を含む．
% プログラムは書き始める前に調を選んでいるので，全トークンに 24 種のうちの真の調が付く．
% プログラムは調をほぼ一様に引く：テスト分割では，どの長調も 214k から 239k トークンを占める（最大/最小 1.12）ので，希少な調は存在しない．
% モデルはこのラベルを決して見ない：プローブの訓練と採点にだけ使う．
% 語彙は 124 記号——小節，位置，絶対 MIDI 音高，音の長さ，構造記号——で，調・和音・音度の記号が混入していないことを単体テストで確認する．
We need the true key at every note, so we generate the training data ourselves.
A program that follows textbook harmony rules picks a key and writes each chord for four voices, optionally adding a melody.
It produces $200$k/$10$k/$10$k pieces for training, validation, and test, each $278$--$508$ tokens long and containing $0$--$3$ key changes.
Because the program picked the key before writing, every token carries its true key, one of the $24$ classes.
The program draws keys near-uniformly: in the test split every major key occupies between $214$k and $239$k tokens (max over min, $1.12$), so no key is rare.
The model never sees these labels: they only train and score the probe.
The vocabulary holds $124$ symbols---bars, positions, absolute MIDI pitches, note lengths, and structural marks---and a unit test checks that no key, chord, or scale-degree symbol slips in.

% 4.2 モデル
\subsection{Models}
% 我々のモデルは 8 層・幅 512・約 25M パラメータの GPT-2 型デコーダである．
% 次トークン予測を目標に，移調による増強あり/なしで各3シード訓練し，計6モデルを得る．
% 別立ての審査モデルは同じアーキテクチャだが，異なるシードと重複しないデータ片を見る．
% 審査モデルはプローブも編集もしない：編集後の音楽がまだ音楽に見えるかを評価するだけであり，どのモデルも自分の出力を採点しない．
% 6モデルはすべて事前に設定した品質ゲートを通る：検証データの次トークン top-1 精度が 0.878–0.881 で，最頻トークンを当てるだけの 0.434 を上回る．
% さらに，我々が訓練していない公開モデルを1つ調べる：Anticipatory Music Transformer で，原著者が Lakh MIDI，MetaMIDI，FMA で訓練したものであり，評価は人手の調ラベルが付いたバッハのコラール 300 曲で行う．
% このモデルではプローブを，モデルがまさに音高を選ぼうとする位置で読む：（時間，長さ，音）というエンコーディングがその規約を強制するためである．音の後で読むと判定が反転することは補足資料に示す．
Our model is a GPT-2 style decoder~\cite{vaswani2017attention,radford2019gpt2} with $8$ layers, width $512$, and about $25$M parameters.
We train it for next-token prediction, with and without transposition augmentation and with three random seeds each, which gives six models.
A separate judge model shares the architecture but sees a different seed and a disjoint slice of the data.
We never probe or edit the judge; it only rates whether edited music still looks like music, so no model grades its own output.
All six models pass a quality gate that we set in advance: next-token top-$1$ accuracy of $0.878$--$0.881$ on validation, against $0.434$ for always guessing the most frequent token.
We also study one public model that we did not train: the Anticipatory Music Transformer~\cite{thickstun2023anticipatory}, which its authors trained on Lakh MIDI~\cite{raffel2016lakh}, MetaMIDI~\cite{ens2021metamidi}, and FMA~\cite{defferrard2017fma}, and which we evaluate on $300$ Bach chorales~\cite{hadjeres2017deepbach,huang2017coconet} with human key labels~\cite{gotham2023wheninrome}.
In that model we read the probe at the positions where it is about to choose a pitch, because its (time, duration, note) encoding forces that convention; the supplementary shows that the verdict flips if we read after the note instead.

% 4.3 測るもの
\subsection{What We Measure}
\label{sec:measures}
% 指標と成功の規則は，対応する実験を走らせる前にすべて固定した．
% プローブの成功規則：床を引いたプローブの点数が，最良の音符数えベースラインを，ゼロを含まない曲単位のブートストラップ 95% 信頼区間で上回ること．
% 編集には，2つの指標と1つの限度を使う．
% 第1の指標は成功率であり，KS 推定器で判定した継続が，書き込んだ調とちょうど一致する割合である．
% 第2の指標は，継続の音のうち与えられた音階に属する割合であり，調の推定器をまったく必要としない．
% 限度は音楽としての品質を守る：編集を1回も走らせる前に，検証データ中 7,989 件の自然な転調で審査モデルのパープレキシティがどれだけ上がるかを測り，その 90 パーセンタイルである 0.613 を，編集に許す上限として固定した．
% 公開モデルでは同じ限度をコラールの自然な転調から測り直し，審査には別の公開チェックポイントを使う．
% したがって編集が音楽を乱してよいのは本物の転調と同程度までである．
% 限度を超えた継続は分母に残したまま失敗として数える：除外は一切しない．
% 割合そのものには基準が必要なので，同じ書き込みをランダムな方向へ行った場合を下限として必ず併記する．
We fixed every measure and every rule for success before the corresponding run.
For the probe, success means that the floor-corrected probe score beats the best note-counting baseline, with a bootstrap $95\%$ confidence interval over pieces~\cite{efron1987bca} that excludes zero.
For the edit we use two measures and one limit.
The first measure is the success rate: how often the continuation, as judged by the KS estimator, is in exactly the key we installed.
The second is the share of continuation notes that belong to a given scale, which needs no key estimator at all.
The limit protects musical quality: before we ran a single edit, we measured how far the judge model's perplexity rises across $7{,}989$ natural key changes in the validation data and fixed the $90$th percentile of that rise, $0.613$, as the most an edit may cost.
For the public model we measure the same limit again from the natural key changes in the chorales, and we use a different public checkpoint as the judge.
An edit may therefore disturb the music at most as much as a real key change does.
A continuation that breaks the limit stays in the denominator and counts as a failure; we exclude nothing.
A rate on its own means little, so we report every rate against the same write into random directions, which gives its floor.

% 4.4 探索段階と最終テスト
\subsection{Search Stage and Final Test}
\label{sec:confirm}
% 介入には多くの選択が伴い，主要な数値を出すのと同じデータで選ぶと数値が水増しされるので，研究を2段階に分けた．
% 第1段階は 8 層 × 3 種類の方向を 100 プロンプトで比べ，最良の組み合わせ（第4層のプローブ方向）を同じプロンプトで採点した（そのプロンプトはプローブの訓練にも使われている）：12 の調については多重比較を補正したが，この探索については補正していない．
% したがって第1段階は「テスト」ではなく「探索」として報告する．
% 第2段階は，プローブもそれ以前のどの実験も見ていないテスト分割の領域から，新規の 100 プロンプトを引く．
% 層・方向・タイミング・標的の調・ベースライン・品質の限度・指標・検定・シード・標本サイズをバージョン管理された文書に書き，この段階の最初の数値が出る前にコミットした．計画からのずれはすべて記録し，我々に不利な結果も報告する．
% 層や方向の探索は繰り返さない．
% 偏った標的推定が何を捏造しうるかは 5.5 節が示すので，標的そのものもここで検証した：どの長調もクラス平均に 7,530 から 9,237 位置を寄せており（最大/最小 1.23），退化した平均は1つもない．
% 標的の調がプロンプトの調と同じ編集は主解析から外し，サニティチェックとして別に報告する．
An intervention involves many choices, and picking them on the data that also produces the headline number inflates it, so we ran the study in two stages.
The first stage compared $8$ layers and $3$ kinds of directions on $100$ prompts and scored the best combination (probe directions at layer~$4$) on those same prompts, which the probe had also been trained on; we corrected for the $12$ keys~\cite{holm1979} but not for that search.
We therefore report the first stage as a search, not as a test.
The second stage draws $100$ fresh prompts from a region of the test split that neither the probe nor any earlier run has seen.
We wrote every such choice---the layer, the directions, the timing, the target keys, the baselines, the quality limit, the measures, the tests, the seeds, and the sample size---into a version-controlled document and committed it before the first number of this stage existed; we log every departure from it and report the results that went against us.
We repeat no search over layers or directions.
Because Section~\ref{sec:wild} shows what an imbalanced estimate of the targets can fabricate, we also checked the targets here: every major key contributes between $7{,}530$ and $9{,}237$ positions to its class mean (max over min, $1.23$), and no mean is degenerate.
We leave out edits whose target key equals the key of the prompt and report them separately as a sanity check.

% 5. 結果
\section{Results}
\label{sec:results}

% 本節では第1節の主張を順に検証する．見出しの数値は移調増強ありシード0のモデルのものであり，増強ありの第2シードは探索段階の全ての判定を再現する．
In this section, we take the claims of Section~\ref{sec:intro} in order; headline numbers come from the transposition-augmented model with seed $0$, and a second augmented seed replicates every search-stage verdict.

% 5.1 調を読む
\subsection{Reading the Key}
\label{sec:h1}
% モデルは調を自力で求めており，入力の表面から写しているのではない．
% 第4層でプローブは macro-F1 0.927 に達し，最良の音符数えベースラインは 0.790，シャッフルの床は 0.032 なので，床を引いたマージンは +0.105（ブートストラップ 95% CI [0.091, 0.114]）である．
% このマージンは6モデルすべての第1–7層でゼロを上回るので，事前に決めた規則は 6/6 で成立する．
% 負になるのは生の埋め込み（−0.20）だけで，そこでは音符そのものが勝って当然であり，未訓練のモデルは 0.243 にとどまる．
The model works out the key; it does not copy it off the surface of the input.
At layer~$4$ the probe reaches macro-$F_1$ $0.927$, the best note-counting baseline reaches $0.790$, and the shuffled-label floor is $0.032$, so the corrected margin is $+0.105$ (bootstrap $95\%$ CI $[0.091,0.114]$).
This margin stays above zero in layers $1$--$7$ of all six trained models, so the rule we set in advance holds in $6/6$ cases.
It turns negative only at the raw embedding ($-0.20$), where the notes themselves should indeed win, and an untrained model reaches only $0.243$.

% より長い履歴を与えてもこの差は埋まらない．
% 上の音符数えベースラインは最大 64 トークンしか見ないので，これを履歴全体へ広げ，新しい音を重く数える版と，短い窓と長い窓をつないだ版も加えた：これらは W=96 で 0.801 と頭打ちになり，W=512 では 0.752 まで下がる（転調前の音符が数え上げを誤った方向へ引っぱる）．
% 最も強い版（0.824）に対してもマージンは +0.071 [0.056, 0.081] なので，活性がこれらの音符数えより調を線形に読みやすくしていると主張する——音符のあらゆる関数に勝つとは主張しない．
A longer history does not close this gap.
The note-counting baseline above sees at most $64$ tokens, so we extended it to the whole prefix and added a recency-weighted version and a version that joins a short and a long window: these peak at $0.801$ for $W{=}96$ and fall to $0.752$ at $W{=}512$, because notes from before a key change pull the count the wrong way.
Against the strongest of them ($0.824$) the margin is still $+0.071$ $[0.056,0.081]$, so we claim that the activation makes the key easier to read linearly than these note counts do---not that it beats every function of the notes.

% 5.2 調を上書きする
\subsection{Overwriting the Key}
\label{sec:h3}
% 調の上書きは音楽を書き込んだ調へ移し，ランダムな上書きは移さない．
% 最終テストの新規 100 プロンプト（図3）では，編集の成功率は 0.356，ランダムベースラインは 0.039 で，比は 9.1 である．
% 12 の標的の調はすべて補正後に分離し（最悪で p=4.8×10^-5，効果量 r=0.72–1.00），プロンプト単位の差のブートストラップ 95% 信頼区間は [0.284, 0.347] である．
% 品質の限度は編集の 84% を通し，限度を課さない場合の同じ割合は 0.410 であり，音符も移る（継続の音の 0.936 が書き込んだ調に，0.617 がプロンプトの調に属する）．
% 長さを揃えたランダムベースライン（3.2節）は 0.056 にとどまり，編集は補正後 12/12 の調でこれと分離する．
% さらに，2つのランダムベースラインはいずれも編集より品質の限度を通りやすく（0.96 と 0.93 対 0.84），限度を課さなくても 0.041 と 0.059 にしか届かない．
% したがって効果は，どの方向に書き込むかから生じており，活性をどれだけ強く押すかから生じているのでもなく，限度がベースラインを不利にしているのでもない．
% プロンプトが既にいる調をそのまま書き込んだ場合，モデルはそこに留まり（0.650），何もしない編集は編集なしの出力をトークン単位で再現する（100/100）：どちらも本来そうあるべき挙動である．
Overwriting the key moves the music into the key we install, and a random overwrite does not.
On the $100$ fresh prompts of the final test (Fig.~\ref{fig:confirm}), the edit reaches a success rate of $0.356$ against $0.039$ for the random baseline, a ratio of $9.1$.
All $12$ target keys separate after correction (worst $p=4.8\times10^{-5}$, effect size $r=0.72$--$1.00$), and the prompt-by-prompt difference has a bootstrap $95\%$ CI of $[0.284,0.347]$.
The quality limit admits $84\%$ of edits, the same rate without that limit is $0.410$, and the notes cross over as well ($0.936$ of them in the installed key against $0.617$ in the prompt's).
The length-matched random baseline of Section~\ref{sec:methodB} reaches $0.056$, and the edit separates from it in $12/12$ keys after correction.
Both random baselines also pass the quality limit more often than the edit does ($0.96$ and $0.93$ against $0.84$), and without that limit they still reach only $0.041$ and $0.059$.
The effect therefore follows from which directions we write to, and not from how far we push the activation or from a limit that penalises the baselines.
When we install the key the prompt is already in, the model simply stays there ($0.650$), and the do-nothing edit reproduces the unedited output token by token ($100/100$), as both should.

% 狙った調に着地するか．編集は元の調から離れるだけでなく，新しい調に着地する．
% 新規プロンプトでは，継続の推定調が書き込んだ調と一致するのは 41.0% で，ランダムベースラインでは 4.1% である．一方，プロンプトの調に留まるのは 8.5% だけで，ランダムベースラインでは 51.7% である．
% 残りの大部分は五度隣の調に落ちる（34.8%）が，これは KS 推定器が混同することが知られている調である．
% したがって編集は，今の調を単に壊すのではなく，特定の調を1つ据え付けている．
\textbf{Specificity.} The edit does not merely leave the old key; it lands on the new one.
On the fresh prompts, the estimated key of the continuation matches the key we install $41.0\%$ of the time, against $4.1\%$ for the random baseline, while only $8.5\%$ of continuations stay in the key of the prompt, against $51.7\%$.
Most of what remains falls on the neighbour a fifth away ($34.8\%$), which the KS estimator is known to confuse.
The edit therefore installs one specific key rather than merely disrupting the current one.

% 5.3 フィードバックの前の次の音
\subsection{The Next Note, Before Any Feedback}
\label{sec:nextpitch}
% 編集は，モデルが書いた音が戻ってくる前に，次の決定を変える．
% 編集を続けた場合の代替説明が1つある：編集が最初の数音を乱し，モデルが自分の出力から調を読み直したのではないか，というものである．
% この説明は，3.2節の生成を伴わない読み取りで排除する．採点には，4.3節で固定した2つの量を使う．
% 編集は，書き込んだ調の側への対数比を 0.695 上げるのに対し，ランダムベースラインは 0.041 しか上げない．
% 書き込んだ音階の上の質量は，編集なしの 0.547 から 0.255 上がり，ベースラインでは 0.017 である．
% この分離は補正後に 12/12 の調で成立し，最悪でも p=5×10^-16，効果量は r≥0.99 である．
% 生成が始まった後は逆になる：一度書き込むと音符は何小節も新しい調に留まるが，その1小節のトークンを継ぎ足すだけで効果全体が再現されるので，モデルは各ステップで音符から調を読み直しており，自分が書いたもの以外に調の記憶を持たない．
The edit changes the model's next decision before any note it wrote can feed back.
A sustained edit leaves one alternative explanation: the edit may disturb the first few notes, and the model may then read the key back off its own output.
We rule that out with the generation-free reading of Section~\ref{sec:methodB}, scored with the two quantities of Section~\ref{sec:measures}.
The edit raises the log ratio toward the installed key by $0.695$, while the random baseline raises it by $0.041$.
The mass on the installed scale rises by $0.255$ from $0.547$ without an edit, against $0.017$ for it.
The separation holds in $12/12$ keys after correction, with a worst case of $p=5\times10^{-16}$ and an effect size of $r\ge0.99$.
Once generation starts the picture reverses: after a single write the notes stay in the new key for many bars, yet splicing in the tokens of that one bar reproduces the whole effect, so the model reads the key back off the notes at every step and keeps no memory of it apart from what it has written.

% 5.4 調が読める場所と，効く場所
\subsection{Where the Key Is Read and Where It Acts}
\label{sec:h5}
% 調が読める層は，モデルがそれを使う層ではない．
% プローブは広い帯で平らになる（第2–6層で macro-F1 0.920–0.929）のに，各層を順に編集してランダムベースラインを差し引くと，ネットワークの中央に単一のピークが残る（最良の層と中央値の差の信頼区間は [0.038, 0.109] でゼロを含まない）：第0–1層ではプローブがすでに調をよく読めるのに，編集はほとんど何も起こさない（図2）．
% 探索段階は残る2つの比較も閉じた：ある層の方向は別の層に書き込んでも働き，編集はプロンプト自体を移調したときに動く距離の 58% を覆った．
% これらは探索段階のデータであり，最終テストで層のスイープを繰り返していないので，検証済みの主張ではなく観察として報告する．
The layers where we can read the key are not the layers where the model uses it.
The probe is flat across a wide band (macro-$F_1$ $0.920$--$0.929$ for layers $2$--$6$), yet editing each layer in turn and subtracting the random baseline leaves a single peak in the middle of the network (best against median, CI $[0.038,0.109]$): at layers~$0$ and~$1$ the probe already reads the key well and the edit does almost nothing (Fig.~\ref{fig:layers}).
The search stage also closed the last two comparisons: one layer's directions still worked when written at another layer, and the edit covered $58\%$ of the distance that transposing the prompt itself covers.
These are search-stage data and we did not repeat the sweep on held-out prompts, so we report the profile as an observation rather than as a tested claim.

% どのトークン位置に書き込むかも，層の深さと同じくらい効く．
% 音高の位置だけに書き込むと何も起こらず（成功率 0.077，ランダムベースラインの床と同じ）音楽も無傷のままだが，小節と音の長さの位置だけに書き込むと効果全体の 69% を運ぶ．
% 最終テストは両方の半分を再現する：音高位置のみの書き込みは 0.036 で，ランダムベースラインの床 0.039 を下回り，分離するのは 0/12 の調である．一方，小節と音の長さの位置のみの書き込みは 0.233，すなわち効果全体の 65% に達し，11/12 で分離する．
% 音高位置のみの書き込みは，たしかに品質の限度内に収まる継続が多い（98% 対 84%）が，それは音楽をほとんど変えていないからにすぎない．
% 音高の確率を単に押すだけの介入なら，逆の振る舞いを示すはずである．
% したがって値が線形に読めることは，それがどこで使われるかの手掛かりとしては弱く，最も読み取りやすい方向が最もよくステアリングできる方向ではないという言語モデルでの報告と一致する．
% 編集は，調が最も読みやすい場所でこそ効かない．
The positions we write to matter as much as the depth.
Writing only at pitch positions does nothing (success rate $0.077$, at the floor set by the random baseline) and leaves the music intact, while writing only at bar and note-length positions carries $69\%$ of the full effect.
The final test reproduces both halves: writing only at pitch positions reaches $0.036$, below the random-baseline floor of $0.039$, and separates from it in $0/12$ keys, while writing only at bar and note-length positions reaches $0.233$, or $65\%$ of the full effect, and separates in $11/12$.
Writing only at pitch positions does keep more continuations inside the quality limit ($98\%$ against $84\%$), but only because it barely changes the music.
An intervention that merely pushed on pitch probabilities would behave the other way around.
Reading a value linearly is therefore a weak guide to where that value is used, which matches the report from language models that the direction easiest to read is not the one that steers best~\cite{wu2025axbench,arad2025selecting}.
The edit fails exactly where the key is easiest to read.

% 5.5 公開モデル
\subsection{A Public Model}
\label{sec:wild}
% どちらの結果も，第4節の公開モデルへそのまま移る．
% プローブは音符数えベースラインを +0.196 [0.132, 0.260] 上回る．
Both results carry over to the public model of Section~\ref{sec:exp}.
The probe beats the note-counting baselines by $+0.196$ $[0.132,0.260]$.

% 編集も移る．
% 編集はランダムベースラインの 7.8 倍に達し（0.479 対 0.061），12/12 の標的で分離し，継続の 99.7% を限度内に保ち，音符も移す（書き込んだ調に 0.890，プロンプトの調に 0.753）．
% ここでも，効く層（第8層）は最もよく読める層（第10層）ではない．
The edit transfers too.
It reaches $7.8\times$ the random baseline ($0.479$ against $0.061$), separates all $12$ targets, keeps $99.7\%$ of continuations inside the limit, and moves the notes across as well ($0.890$ of them in the installed key against $0.753$ in the prompt's).
Here too the layer that acts (layer~$8$) is not the layer that reads best (layer~$10$).

% 最初の実験で得た結果のうち1つは撤回する：嬰ヘ長調への「学習された好み」に見えたものは，その調が一度も現れないコーパスから標的を推定したことによる産物であり，補足資料に訂正後の数値を載せる．
One first-run finding did not survive its control and we withdraw it: what looked like a learned preference against F$\sharp$ major came from estimating the targets on a corpus in which that key never occurs, and the supplementary reports the corrected numbers.

% 6. 限界
\section{Limitations}
\label{sec:limits}
% 本研究が主張しないことを明示する．
% 書き込むのは長調だけである：短調は二次的な条件として登録したが，まだ走らせていない．
% KS 推定器は五度違いの調を混同するので，音階に属する音の割合も併せて報告している．
% 品質の限度は，編集が参照モデルをどれだけ乱すかを測るもので，音楽としての良さそのものではなく，聴取実験は行っていない．
% 公開モデルの結果は1つのサイズの1つのチェックポイントに限られ，設計も当初のまま——層は別のプロンプトで選び，限度は評価の前に固定したが，2度目の最終テストは行っていない——である．
% モデル規模と幾何に関する測定は補足資料で報告する．
% 短調と聴取実験は今後の課題とする．
We state what this study does not claim.
We install major keys only; we registered minor keys as a secondary condition and have not run them.
The KS estimator confuses keys a fifth apart, which is why we also report the share of notes that belong to the scale.
Our quality limit measures how far an edit disturbs a reference model, not musical quality itself, and we ran no listening test.
The public-model result covers one checkpoint at one size, and it keeps its original design, in which we chose the layer on separate prompts and fixed the limit before evaluation but did not run a second final test.
The supplementary reports our scaling and geometry analyses.
We leave minor keys and a listening test for future work.

\section{Conclusion}
% 音楽 Transformer は自分が何の調にいるかを知っているのか——書き換えが答えを与える：音楽は，我々が書き込んだ調に従う．
% 我々が編集した対象を世界モデルと呼ぶ読者もいるだろうが，我々はその語を結果ではなく解釈として用いる．
% テストベッド，設計を固定した文書，デモを以下で公開する．
% TBD（作業）：匿名リポジトリを投稿前に作成し，URL を差し替える．
We asked whether a music Transformer knows what key it is in, and overwriting settles it: the music follows the key we write in.
Readers may call the thing we edit a world model; we use that term as an interpretation, not as a result.
